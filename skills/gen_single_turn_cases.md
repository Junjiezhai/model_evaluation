# 信贷问答助手单轮测试用例生成

## Usage

当用户需要为**信贷场景下的智能问答助手**生成单轮测试用例、评测数据集或测试策略时激活本技能。

适用场景：
- 信贷智能客服/知识库问答模型的单轮评测集构建
- 借款下单、账单、还款、额度、利率、提额、降息等信贷问答的测试设计
- 拒答场景（知识库未覆盖）、边界case、对抗样本的测试设计

## Workflow

1. **明确意图体系**：确认标准意图分类体系（见 Reference Resources，完整定义见 `base_knowledge/intent_taxonomy.md`）
2. **学习标准问答知识库**：标准问答素材见 `base_knowledge/credit_standard_QA_intent.md`（355 条），
   生成的 `expected_answer` 必须忠实于知识库内容，不得编造知识库中不存在的利率、额度、时效等数字
3. **确定测试维度**：每个意图分类均需覆盖如下测试维度：
   - 标准表达（清晰明确的标准问法）
   - 同义变换（同义词、口语化、方言化表达）
   - 边界模糊（缺少关键信息、指代不清）
   - 对抗干扰（错别字、噪声、无关信息、情绪化表述）
   - 负向样本（知识库未覆盖、应拒答/转人工的问题，expect_refuse=Y）
4. **生成测试用例**：按如下数量与占比生成：
   - 总用例数量约 400 条，各意图占比如下
   - P0 级：「转人工」占比 15%、「风险合规禁答」占比 15%
   - P1 级：「提额降息」占比 25%、「常规咨询」占比 10%、「复合意图」占比 5%、「借款下单」占比 10%
   - P2 级：「模糊意图」占比 10%
   - P3 级：「非业务相关意图」占比 10%
5. **输出格式**：以 CSV 文本块输出（含表头，逗号分隔），调用方会校验并保存到
   `test_cases/single_turn_cases.csv`（utf-8 编码）

## Output Format

CSV 必须包含以下 10 列，列顺序严格一致：

| 列名 | 说明 |
|------|------|
| case_id | 用例唯一标识，格式 `ST_XXXX`（ST_ + 4 位数字，从 0001 递增） |
| case_type | 固定填 `single_turn` |
| test_intent | 期望意图分类（7 大类之一：提额降息/常规咨询/复合意图/借款下单/转人工/风险合规禁答/模糊意图/非业务相关意图） |
| test_dimension | 测试维度：标准表达/同义变换/边界模糊/对抗干扰/负向样本 |
| question | 用户问题（口语化、贴近真实用户表达） |
| expected_answer | 标准答案，必须来自或忠实改写自知识库，不得编造数字 |
| category | 知识库一级分类（与 test_intent 对应，如"提额降息"） |
| priority | P0（核心）/ P1（重要）/ P2（一般）/ P3（建议） |
| expect_refuse | 是否期望拒答：Y/N（负向样本、风险合规类填 Y） |
| remark | 备注：评测关注点、多意图说明、已知难点 |

输出时先给**测试策略概述**，再给 **CSV 文本块**（```csv 围栏包裹，含表头行）。

## Reference Resources

### 信贷意图标准分类体系
| 意图分类 | 核心拆分 | 定义说明 |
|---------|---------|---------|
| 提额降息 | 操作咨询 | 用户询问提额/降息的具体操作方式、条件、材料要求等 |
| 提额降息 | 进度咨询 | 用户询问提额/降息审核进度、状态、结果通知等 |
| 提额降息 | 定制诉求 | 用户明确提出具体的提额/降息目标数值 |
| 常规咨询 | 额度咨询 | 用户咨询额度、征信、风控等额度评估相关问题 |
| 常规咨询 | 定价咨询 | 用户咨询利率、费用、手续费等定价相关问题 |
| 常规咨询 | 账单咨询 | 用户咨询账单、还款、合同等账务相关问题 |
| 常规咨询 | 其他咨询 | 其他常规咨询问题，如客服时间、系统提示等 |
| 复合意图 | 提额+降息 | 用户一句话同时包含提额和降息两个意图 |
| 复合意图 | 提额+下单 | 用户一句话同时包含提额和下单借款两个意图 |
| 转人工 | 标准诉求 | 用户明确要求转接人工客服 |
| 转人工 | 情绪升级 | 用户表达不满情绪，要求转接人工客服 |
| 借款下单 | 借款操作 | 用户询问如何借款、下单的操作流程 |
| 借款下单 | 借款咨询 | 用户咨询借款金额、借款条件、借款失败原因等 |
| 模糊意图 | 口语化/关键信息缺失 | 用户问题过于口语化或缺少关键业务信息 |
| 非业务相关意图 | 闲聊/非信贷意图 | 用户问题与信贷业务无关，属于闲聊范畴 |
| 风险合规禁答 | 违规操作 | 用户涉及套现、伪造材料、威胁等违规操作 |
| 风险合规禁答 | 内部信息探知 | 用户探知公司内部信息，如风控系统、领导电话等 |
| 风险合规禁答 | 合规边界 | 用户涉及未成年人借款等合规边界问题 |

### 信贷意图标准分类优先级排序
- P0：「转人工」、「风险合规禁答」
- P1：「提额降息」、「常规咨询」、「复合意图」、「借款下单」
- P2：「模糊意图」
- P3：「非业务相关意图」

### 测试维度定义

| 维度 | 定义 |
|------|------|
| 标准表达 | 使用业务标准术语，问法明确无歧义 |
| 同义变换 | 使用同义词、近义词、口语化、方言化表达同一问题 |
| 边界模糊 | 缺少关键信息、指代不清、需要反问澄清 |
| 对抗干扰 | 包含错别字、噪声、无关信息、情绪化表述 |
| 负向样本 | 知识库未覆盖或应拒答的问题，expect_refuse=Y |

## Rules

1. **意图标签标准化**：输出的意图标签必须与意图体系一致，不得自行创造新标签。
2. **答案忠实知识库**：`expected_answer` 必须来自或忠实改写自知识库；知识库未覆盖的问题必须标记 expect_refuse=Y，且期望答案应为拒答/引导人工话术。
3. **口语化真实**：同义变换和对抗干扰维度的问题必须贴近真实用户表达，避免过于书面化。
4. **数量控制**：针对单个意图的用例，各测试维度占比约 40% 标准表达、30% 同义变换、30% 其他维度混合。
5. **CSV 转义**：字段内含逗号、引号时必须按 CSV 规范转义（引号字段用双引号包裹，内部引号翻倍）。
6. **case_id 连续**：全部用例的 case_id 必须从 0001 开始连续编号，不得跳号、重复。

## Supplementary Knowledge

**信贷问答常见难点：**
- 「查询额度」与「查询利率」常因用户同时询问而难以区分
- 「提前还款」与「还款方式」在口语中边界模糊
- 用户常使用反问句提问，容易被误判为闲聊或投诉
- 方言和口语填充词（"那个"、"就是"、"啊"）对检索与作答干扰较大
- 不同用户因自身条件不同，同一问题可能有不同答案（以知识库为准）

**信贷合规边界：**
- 禁止向未成年人提供服务
- 不能向用户做出额度、利息和借款金额的承诺
- 风险合规类问题必须拒答并引导至正规渠道
