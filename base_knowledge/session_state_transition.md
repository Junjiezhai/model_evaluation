# 信贷客服会话状态转移矩阵

> **文档用途**：定义信贷客服场景下的完整会话状态机，用于对话管理系统（Dialogue Management System）的设计与实现。
>
> **关联文件**：
> - `intent_taxonomy.md` — 意图分类体系
> - `standard_QA_intent.md` — 标准问答库（355条用例）
> - `skills/gen_single_turn_cases.md` — 单轮测试用例生成技能

## 1. 会话状态定义

### 1.1 状态编码规范

状态编码采用 **3字母业务域 + 2字母状态语义** 的格式：

- `TL` — 提额（TiE）
- `JX` — 降息（JiangXi）
- `JK` — 借款（JieKuan）
- `ZX` — 咨询（ZiXun）
- `FH` — 复合（FuHe）
- `RG` — 人工（RenGong）
- `FX` — 风险（FengXian）
- `MH` — 模糊（MoHu）
- `FY` — 非业务（FeiYeWu）
- `INIT` — 初始状态
- `END` — 结束状态

### 1.2 用户会话状态枚举

## 2. 状态转移矩阵

### 2.1 提额主流程状态转移

| 当前状态 | 用户意图/问题 | 系统应答动作 | 下一状态 |
|---------|-------------|-----------|---------|
| `INIT`（初始） | 提额业务咨询 | `ACT_YWJS` 业务知识介绍 | `TL_YWZX`（提额业务咨询态） |
| `TL_YWZX` | 提额准入条件咨询 | `ACT_ZRTJ` 准入条件陈述 | `TL_ZRTJ`（资质确认态） |
| `TL_ZRTJ` | 提额操作咨询 | `ACT_CQZY` 提额操作指引 | `TL_CQZX`（操作咨询态） |
| `TL_CQZX` | 提额材料咨询 | `ACT_CLQY` 材料要求说明 | `TL_CLZX`（材料咨询态） |
| `TL_CLZX` | 材料已上传/补件完成 | `ACT_YDBJ` 引导补件 → 确认材料齐全 | `TL_JDZX`（进度查询态） |
| `TL_JDZX` | 提额进度咨询 | `ACT_JDJG` 进度查询结果 | `TL_JGZX`（结果查询态） |
| `TL_JGZX` | 提额结果咨询 | `ACT_JGYZ` 结果告知 | `TL_JG`（结果态） |
| `TL_JG` | 审核通过 | `ACT_YDXD` 引导下单/借款 | `JK_CQZX`（引导至借款操作态） |
| `TL_JG` | 审核失败 | `ACT_YDTE` 引导提额/重新申请 | `TL_CQZX`（回到操作咨询态） |

|---------|-------------|-----------|---------|

| `JX_YWZX` | 降息准入条件咨询 | `ACT_ZRTJ` 准入条件陈述 | `JX_ZRTJ`（资质确认态） |
| `JX_ZRTJ` | 降息操作咨询 | `ACT_CQZY` 操作指引 | `JX_CQZX`（操作咨询态） |
| `JX_CQZX` | 材料补充完成 | `ACT_JDJG` 进度查询 | `JX_JDZX`（进度查询态） |
| `JX_JDZX` | 进度咨询 | `ACT_JDJG` 进度查询结果 | `JX_JGZX`（结果查询态） |

### 2.3 借款下单流程状态转移

| 当前状态 | 用户意图/问题 | 系统应答动作 | 下一状态 |
|---------|-------------|-----------|---------|

|---------|-------------|-----------|---------|
| `INIT`（初始） | 额度查询 | `ACT_EDCX` 额度查询结果 | `ZX_EDCX`（额度查询态） |

| `ZX_EDCX` | 额度查询后 — 系统主动引导降息 | `ACT_YDTE` 引导降息（主动推荐降息方案） | `JX_CQZX`（降息操作态） |

| `ZX_DJCX` / `ZX_ZDCX` | 用户有借款意向 | `ACT_YDXD` 引导下单 | `JK_CQZX`（借款操作态） |

### 2.5 复合意图流程状态转移

| 当前状态 | 用户意图/问题 | 系统应答动作 | 下一状态 |
|---------|-------------|-----------|---------|
| `INIT`（初始） | 提额+降息复合 | `ACT_YWJS` 分别介绍 + `ACT_CQZY` 操作指引 | `FH_TLJX`（复合处理态） |
| `FH_TLJX` | 先处理提额 → 再处理降息 | `ACT_YDTE` 引导提额 | `TL_CQZX` → `JX_CQZX` |
| `INIT`（初始） | 提额+下单复合 | `ACT_YWJS` 分别介绍 + `ACT_YDTE` 引导提额 | `FH_TLXD`（复合处理态） |
| `FH_TLXD` | 先提额 → 再借款 | `ACT_YDTE` 引导提额 | `TL_CQZX` → `JK_CQZX` |

### 2.6 异常处理流程状态转移

> **全局规则**：以下 P0 级转移适用于**所有状态**，即用户在任何业务状态（提额中、降息中、借款中、咨询中等）下识别到以下意图时，应立即触发对应转移，无需等待当前业务流程完成。

| 当前状态 | 用户意图/问题 | 系统应答动作 | 下一状态 |
|---------|-------------|-----------|---------|
| `INIT` / **任意状态** | 违规操作 | `ACT_FXJJ` 风险拒绝 | `FX_WGCZ`（风险拒绝态）→ `END` |
| `INIT` / **任意状态** | 内部信息探知 | `ACT_FXJJ` 风险拒绝 | `FX_NBXX`（风险拒绝态）→ `END` |
| `INIT` / **任意状态** | 合规边界 | `ACT_FXJJ` 风险拒绝 + 合规解释 | `FX_HGBJ`（合规边界态）→ `END` |
| `INIT` / **任意状态** | 用户主动要求转人工 | `ACT_RGFW` 转人工 | `RG_BZSQ`（标准转接态）→ `END` |
| `INIT` / **任意状态** | 用户情绪升级 | `ACT_AFYD` 安抚引导 + `ACT_RGFW` 转人工 | `RG_QX SJ`（情绪处理态）→ `END` |
| `INIT` / **任意状态** | 模型无法完全理解用户意图（非模糊，需反问澄清） | `ACT_FWCL` 反问澄清 | `MH_FWCL`（反问澄清态）→ 等待用户澄清后回原状态或 `INIT` |
| `INIT` / **任意状态** | 用户输入过于模糊/信息严重缺失 | `ACT_MHZD` 模糊引导 | `INIT`（回到初始，等待补充信息） |
| `INIT` / **任意状态** | 非业务相关 | `ACT_LTXZ` 闲聊引导 | `INIT`（回到初始，等待业务问题） |

#### 2.6.1 转人工全局规则详解

转人工是最高优先级的全局转移，覆盖所有业务状态。以下是具体场景示例：

| 业务场景 | 当前状态 | 触发条件 | 转移动作 |
|---------|---------|---------|---------|
| 提额流程中用户不耐烦 | `TL_CQZX` | 用户说"太麻烦了，快给我转人工" | `ACT_AFYD` + `ACT_RGFW` → `RG_QX SJ` |
| 降息流程中用户主动要求 | `JX_CQZX` | 用户说"帮我转人工客服" | `ACT_RGFW` → `RG_BZSQ` |
| 借款咨询中情绪升级 | `JK_CQZX` | 用户说"你们这什么破系统" | `ACT_AFYD` + `ACT_RGFW` → `RG_QX SJ` |
| 信息查询中强烈不满 | `ZX_EDCX` | 用户说"我的额度怎么这么低，叫你们经理来" | `ACT_AFYD` + `ACT_RGFW` → `RG_QX SJ` |

#### 2.6.2 反问澄清与模糊引导的区别

| 维度 | `ACT_FWCL` 反问澄清 | `ACT_MHZD` 模糊引导 |
|------|-------------------|-------------------|
| 触发条件 | 模型能听懂问题但**不完全理解**用户意图（如歧义、多意图混合无法确定优先级） | 用户输入**严重缺失关键信息**（如只有语气词、短语不成句） |
| 系统行为 | **主动提出具体澄清问题**，如："您是想咨询提额还是降息呢？" | **引导用户补充信息**，如："请问您具体想咨询什么问题？" |
| 下一状态 | `MH_FWCL`（反问澄清态）→ 用户澄清后回到原业务状态 | `INIT`（初始态）→ 等待用户重新发起完整问题 |
| 用户体验 | 对话有延续性，模型展示理解尝试 | 对话重新开始，更接近"听不懂，请再说一遍" |

### 4.1 完整链路汇总表

| 业务场景 | 完整状态转移链路 |
|---------|----------------|
| **提额流程** | `INIT` → `TL_YWZX` → `TL_ZRTJ` → `TL_CQZX` → `TL_CLZX` → `TL_JDZX` → `TL_JGZX` → `TL_JG`(成功) → `引导借款` → `JK_CQZX` → `END` |
| **提额流程（失败）** | `INIT` → ... → `TL_JG`(失败) → `引导重新提额` → `TL_CQZX` → ... |
| **降息流程** | `INIT` → `JX_YWZX` → `JX_ZRTJ` → `JX_CQZX` → `JX_JDZX` → `JX_JGZX` → `JX_JG`(成功) → `引导借款` → `JK_CQZX` → `END` |
| **降息流程（失败）** | `INIT` → `JX_YWZX` → `JX_ZRTJ` → `JX_CQZX` → `JX_JDZX` → `JX_JGZX` → `JX_JG`(失败) → `引导提额` → `TL_CQZX` → `END` |
| **借款流程** | `INIT` → `JK_CQZX`/`JK_TJZX` → `引导下单` → `END` |
| **信息咨询** | `INIT` → `ZX_EDCX`/`ZX_DJCX`/`ZX_ZDCX` → **系统主动引导** → `TL_CQZX`(提额) / `JX_CQZX`(降息) / `JK_CQZX`(借款) → `END` |
| **复合意图** | `INIT` → `FH_*` → 分别处理 → `TL_CQZX` → `JX_CQZX`/`JK_CQZX` → `END` |

### 4.2 状态优先级矩阵

| 优先级 | 意图分类 | 对应状态 | 处理策略 |
|--------|---------|---------|---------|
| **P0** | 转人工（全局） | `RG_BZSQ`, `RG_QX SJ` | **任意状态**下识别到用户主动要求或情绪升级，立即转人工，中断当前业务流程 |
| **P0** | 风险合规禁答（全局） | `FX_WGCZ`, `FX_NBXX`, `FX_HGBJ` | **任意状态**下识别到违规/探知/合规边界，立即风险拒绝 |
| P1 | 提额降息 | `TL_*`, `JX_*` | 进入对应主流程；成功 → 引导借款；失败 → 引导重新申请 |
| P1 | 常规咨询 | `ZX_*` | 信息查询后**系统主动引导**至提额/降息/借款（不等待用户表达意向） |
| P1 | 复合意图 | `FH_*` | 拆分为串行子流程 |
| P1 | 借款下单 | `JK_*` | 进入借款流程 |
| **P2** | 反问澄清（全局） | `MH_FWCL` | **任意状态**下模型不完全理解时主动反问澄清；用户澄清后返回原业务状态 |

| P3 | 非业务相关（全局） | `FY_LTXZ` | 礼貌引导回业务，回到INIT |

## 5. 实现建议

### 5.1 状态机实现要点

1. **状态持久化**：每次用户提问后，系统应根据识别到的意图，查询当前状态对应的转移规则，确定下一状态和应答动作。

2. **上下文管理**：会话状态应包含：
   - 当前状态编码
   - 历史状态栈
   - 已收集的用户信息（如额度、利率偏好等）
   - 会话轮次计数

3. **超时处理**：长时间未响应的会话应自动重置到 `INIT` 状态。

### 5.2 复合意图处理策略

1. **意图拆分**：使用意图识别模型将复合意图拆分为多个原子意图。
2. **串行处理**：按优先级排序，依次处理每个原子意图。
3. **状态衔接**：前一个子流程完成后，自动衔接至下一个子流程的初始状态。

### 5.3 异常兜底策略

1. **全局异常捕获**：任何状态下都应支持 P0 级别的异常转移（转人工、风险拒绝）。
2. **转人工兜底**：连续 N 次反问澄清或状态转移失败后，自动建议转人工。
3. **反问降级**：反问澄清后用户仍无法清晰表达时，降级为 `ACT_MHZD` 模糊引导。
4. **情绪感知**：任意业务状态下需持续监测用户情绪信号，一旦识别到不满/愤怒/焦躁等，应立即触发安抚引导并转人工。

### 5.4 主动引导策略

1. **查询后主动引导**：用户查询额度后，系统应主动推荐提额项目；查询定价后，系统应主动介绍降息方案。不应等待用户明确表达意向。
2. **成功后的链式引导**：提额或降息审核通过后，系统应主动引导用户进入借款流程（"额度已提升，是否立即借款？"），形成业务闭环。
3. **引导话术个性化**：根据用户画像（如当前额度利用率、利率水平）调整引导优先级——高利率用户优先引导降息，低额度用户优先引导提额。

### 5.5 反问澄清策略

1. **触发判断**：当意图识别置信度低于阈值（建议 0.7）或识别到多个意图且无法确定优先级时，触发反问澄清。
2. **反问内容**：反问应具体、有指向性，如"您是想咨询提额还是降息呢？"而非"请再说一遍"。
3. **反问次数限制**：单轮会话中反问次数不超过 2 次，超过后自动建议转人工。
